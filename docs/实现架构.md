# 实现架构

## 1. 核心原则

本项目采用 **Explorer 原生桌面图标** 方案。

应用不自绘桌面图标，不替代 Windows 桌面，也不接管图标的打开、右键菜单、拖拽文件等原生行为。应用只负责：

- 识别桌面图标的位置和身份
- 记录、移动、还原桌面图标坐标
- 在桌面上叠加矩形分组背景
- 提供分组区域的拖动、缩放、锁定、主题等管理能力

这样可以最大程度保留 Windows Explorer 的原生体验，同时将实现复杂度控制在可接受范围内。

## 2. 推荐技术栈

| 层级 | 技术选型 | 说明 |
| --- | --- | --- |
| 主语言 | C# / .NET 10 LTS | 适合长期维护，生态成熟 |
| 桌面 UI | WPF | 适合透明窗口、无边框浮层、Win32 互操作 |
| 托盘 | WinForms NotifyIcon | 用于系统托盘图标和右键菜单 |
| Win32 互操作 | Vanara.PInvoke 或 CsWin32 | 封装窗口查找、消息发送、鼠标 Hook 等能力 |
| 持久化 | SQLite | 存储分组、图标位置、快照、用户设置 |
| 日志 | Serilog | 记录 Explorer 交互、恢复失败、异常退出等关键事件 |
| 打包 | 自包含 exe 优先 | 早期方便调试和分发，后期可评估 MSIX |

## 3. 总体架构

应用由以下模块组成：

```text
WinIconManagement
├─ AppHost                 应用生命周期、单实例、托盘入口
├─ SettingsWindow          主设置界面
├─ DesktopOverlay          桌面矩形背景浮层
├─ DesktopIconService      Explorer 桌面图标读写
├─ FenceLayoutService      分组布局、图标排列、坐标计算
├─ MouseInteractionService 桌面框选、拖动、缩放、命中检测
├─ SnapshotService         桌面快照、快速切换
├─ Persistence             SQLite 数据访问
└─ Infrastructure          日志、配置、Win32 封装、异常处理
```

## 4. 核心模块说明

### 4.1 AppHost

负责应用启动和退出闭环。

主要职责：

- 保证应用单实例运行
- 初始化托盘图标
- 注册托盘右键菜单
- 加载用户设置和分组布局
- 启动桌面 Overlay
- 监听 Explorer 重启、显示器变化、DPI 变化
- 退出时恢复图标位置、移除 Overlay、释放 Hook 和托盘资源

托盘菜单第一版包括：

- 主设置
- 固定 / 取消固定
- 退出

菜单结构需要保留扩展能力，后续可以加入：

- 新建分组
- 保存快照
- 切换快照
- 暂停管理
- 日志诊断

### 4.2 DesktopIconService

负责和 Windows Explorer 桌面图标交互，是项目最关键的底层模块。

目标是找到桌面的 `SysListView32` 控件，并通过 ListView 消息读取和设置图标位置。

主要能力：

- 获取桌面 ListView 句柄
- 枚举桌面图标
- 读取图标文本、索引、坐标
- 设置指定图标坐标
- 刷新图标布局
- 检测 Explorer 是否重启

预期使用的 Win32 能力：

- `FindWindow`
- `FindWindowEx`
- `EnumWindows`
- `SendMessage`
- `LVM_GETITEMCOUNT`
- `LVM_GETITEMTEXT`
- `LVM_GETITEMPOSITION`
- `LVM_SETITEMPOSITION32`

注意事项：

- 桌面图标属于 Explorer 进程，跨进程读取文本和坐标需要谨慎处理。
- 图标索引不是稳定身份，不能只依赖 ListView index 做长期存储。
- Explorer 重启、桌面刷新、图标新增删除后，需要重新枚举并做身份匹配。
- 多显示器和 DPI 缩放会影响坐标换算。

### 4.3 DesktopOverlay

负责绘制桌面上的矩形分组背景。

Overlay 是独立的透明无边框 WPF 窗口，覆盖在桌面区域上方、桌面图标下方或尽量贴近桌面层级。它只绘制分组背景和交互辅助元素，不绘制真实图标。

主要能力：

- 绘制半透明矩形背景
- 支持圆角、边框、透明度
- 支持浅色 / 深色模式
- 支持后续扩展自定义颜色
- 绘制分组标题、拖拽手柄、缩放手柄
- 在固定模式下隐藏编辑控件

Hover 策略：

- 支持分组区域 hover 高亮
- 支持边框 hover 高亮
- 支持图标格子背景 hover 辅助效果
- 不直接缩放 Explorer 原生图标
- 不直接修改 Explorer 原生图标阴影

### 4.4 MouseInteractionService

负责桌面层面的鼠标交互。

主要能力：

- 监听桌面长按左键拖动
- 绘制临时框选区域
- 判断框选命中的桌面图标
- 支持分组整体拖动
- 支持分组宽高调整
- 支持固定 / 取消固定状态切换
- 支持拖拽结束后的图标自动排序

实现方式：

- 第一阶段可以使用低级鼠标 Hook 或 Overlay 窗口命中检测。
- 固定模式下，Overlay 尽量鼠标穿透，避免影响 Explorer 原生点击和右键。
- 编辑模式下，Overlay 接收分组背景、边框、手柄区域的鼠标事件。

### 4.5 FenceLayoutService

负责分组内图标排列和坐标计算。

主要能力：

- 根据矩形区域计算可用网格
- 根据系统图标尺寸和间距生成排列坐标
- 将选中的桌面图标移动到矩形区域内
- 拖拽结束后重新排序
- 支持分组区域变化后重新布局
- 支持图标位置固定和解锁

第一版排序策略：

- 从左到右、从上到下排列
- 保留图标进入分组时的顺序
- 分组尺寸不足时允许纵向扩展或提示无法容纳

后续可扩展：

- 按名称排序
- 按类型排序
- 手动排序
- 自动吸附网格
- 分组内分页或滚动

### 4.6 Persistence

负责本地数据存储。

建议使用 SQLite，第一版表结构可以包括：

```text
AppSettings
- Key
- Value

Fences
- Id
- Name
- X
- Y
- Width
- Height
- IsLocked
- ThemeMode
- BackgroundColor
- Opacity
- CreatedAt
- UpdatedAt

FenceIcons
- Id
- FenceId
- IconIdentity
- DisplayName
- OriginalX
- OriginalY
- CurrentX
- CurrentY
- SortOrder
- LastSeenAt

Snapshots
- Id
- Name
- CreatedAt

SnapshotIcons
- Id
- SnapshotId
- IconIdentity
- DisplayName
- X
- Y
```

`IconIdentity` 不能只使用桌面图标名称。建议组合多个信息生成：

- 显示名称
- 解析后的文件路径或 Shell item 标识
- 是否为快捷方式
- 快捷方式目标路径
- 必要时加入创建时间或文件属性辅助匹配

第一版可以先使用 `DisplayName + Path`，后续再增强 Shell item 解析。

## 5. 核心流程

### 5.1 首次框选创建分组

```text
用户在桌面长按左键拖动
-> MouseInteractionService 生成临时矩形
-> DesktopIconService 枚举当前桌面图标
-> FenceLayoutService 判断哪些图标位于矩形内
-> Persistence 记录图标原始坐标
-> FenceLayoutService 计算分组内新坐标
-> DesktopIconService 移动图标到矩形内
-> DesktopOverlay 绘制分组背景
-> Persistence 保存分组和图标关系
```

### 5.2 应用退出

```text
用户点击托盘退出
-> AppHost 停止鼠标 Hook 和 Overlay 交互
-> Persistence 读取托管图标原始坐标
-> DesktopIconService 将图标恢复到原始位置
-> DesktopOverlay 关闭所有背景窗口
-> 释放托盘图标
-> 应用退出
```

退出必须尽量完整清理，避免残留：

- 托盘图标残留
- 透明窗口残留
- 鼠标 Hook 未释放
- 图标位置恢复失败但未记录日志

### 5.3 再次启动

```text
应用启动
-> AppHost 加载上次分组配置
-> DesktopIconService 枚举当前桌面图标
-> Persistence 匹配已托管图标
-> DesktopOverlay 绘制矩形背景
-> FenceLayoutService 计算分组内位置
-> DesktopIconService 将匹配图标移动到分组内
```

如果某些图标不存在：

- 不阻塞应用启动
- 标记为 missing
- 写入日志
- 设置界面中可以提示用户清理失效图标

### 5.4 Explorer 重启恢复

```text
检测到 Explorer 进程或桌面 ListView 句柄变化
-> 重新查找桌面 ListView
-> 重新枚举桌面图标
-> 重新匹配托管图标
-> 重新应用当前分组布局
-> 刷新 Overlay 层级
```

Explorer 重启是必须考虑的场景，否则桌面增强类工具容易出现状态丢失。

## 6. 图标 Hover 能力边界

采用 Explorer 原生图标后，Hover 能力以背景辅助效果为主。

可以稳定实现：

- Windows 原生桌面图标 hover 高亮
- 分组背景 hover 变亮
- 分组边框 hover 变色
- 图标格子背景辅助高亮
- 编辑模式下显示拖动和缩放控件

不建议第一版实现：

- 单个图标缩放
- 单个图标发光
- 单个图标阴影修改
- 单个图标复杂动画

这些效果需要自绘图标或截图镜像浮层，容易造成和 Explorer 原生行为不一致。

## 7. 难点和风险

### 7.1 Explorer 桌面结构不稳定

不同 Windows 版本、主题、虚拟桌面、Explorer 重启后，桌面窗口层级可能变化。

应对方式：

- 封装独立的 DesktopWindowResolver
- 失败时自动重试
- 记录诊断日志
- 设置界面提供“重新连接桌面”功能

### 7.2 图标身份匹配不稳定

桌面图标重命名、快捷方式目标变化、文件删除后，历史记录可能无法准确匹配。

应对方式：

- 第一版使用名称和路径组合
- 后续引入 Shell item 标识
- 匹配失败不强行移动
- 提供失效图标清理能力

### 7.3 多显示器和 DPI

桌面坐标、屏幕坐标、WPF 设备无关像素之间需要转换。

应对方式：

- 所有持久化坐标统一使用物理像素或明确的桌面坐标系
- Overlay 渲染时再转换为 WPF 坐标
- 监听显示器变化和 DPI 变化
- 测试 100%、125%、150% 缩放

### 7.4 Overlay 层级和鼠标穿透

Overlay 既要显示在桌面上，又不能破坏图标原生点击和右键。

应对方式：

- 固定模式默认鼠标穿透
- 编辑模式只让背景、边框、手柄接收鼠标事件
- 图标区域尽量交还给 Explorer
- 必要时提供“暂停管理”开关

### 7.5 退出恢复失败

如果应用异常退出，图标可能停留在分组区域内。

应对方式：

- 每次移动前记录原始坐标
- 启动时检测上次是否异常退出
- 提供“恢复原始桌面布局”按钮
- 提供快照作为额外恢复点

## 8. 分阶段实现计划

### 第一阶段：MVP 闭环

目标：验证 Explorer 原生图标方案可行。

- 单实例 exe
- 托盘图标和右键菜单
- 查找桌面 ListView
- 枚举桌面图标
- 读取和设置图标坐标
- 桌面拖拽框选
- 创建一个矩形分组
- 将框选图标移动到分组内
- 退出恢复原始坐标
- 再次启动恢复分组布局

### 第二阶段：可用性增强

目标：让工具适合日常使用。

- 多分组
- 分组拖动和缩放
- 固定 / 取消固定
- 深色 / 浅色模式
- 透明度设置
- 开机自启动
- Explorer 重启恢复
- 显示器和 DPI 变化处理
- 失效图标处理

### 第三阶段：快照和体验优化

目标：增强长期管理能力。

- 桌面快照
- 快速切换布局
- 分组内排序选项
- 右键托盘菜单扩展
- 设置页中的分组管理
- 日志诊断和一键恢复

### 第四阶段：实验性视觉效果

目标：在不破坏 Explorer 原生行为的前提下增强视觉体验。

- 图标格子 hover 背景
- 拖拽目标占位效果
- 分组背景轻量动画
- 分组标题样式
- 自定义主题颜色

不建议在这个阶段之前尝试图标本体缩放或复杂动画。

## 9. 推荐第一版边界

第一版应该明确只做以下能力：

- 管理真实 Explorer 桌面图标
- 支持一个或多个矩形分组
- 支持基础透明背景和圆角
- 支持拖拽框选创建分组
- 支持应用退出恢复原始布局
- 支持再次启动重新应用分组布局
- 保留桌面图标原生双击、右键、拖拽行为

第一版暂不承诺：

- 图标本体缩放
- 图标本体阴影
- 完全自定义图标动画
- 替代 Explorer 桌面
- 跨虚拟桌面的复杂同步

这个边界可以让项目先完成核心闭环，再逐步逼近 Fences 类产品体验。
