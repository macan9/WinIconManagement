# 05 Explorer 桌面窗口解析

## 目标

稳定找到 Explorer 桌面图标所在的窗口链，为图标枚举、图标移动、Bridge 注入和恢复流程提供基础信息。

核心窗口链：

```text
Progman / WorkerW
  -> SHELLDLL_DefView
    -> SysListView32
```

## 解析内容

`DesktopResolveResult` 至少包含：

- `progmanWindow`
- `workerWindow`
- `workerWindowAfterDefView`
- `shellDefViewWindow`
- `listViewWindow`
- `explorerProcessId`
- `resolvePath`
- `backgroundAnchorWindow`
- `backgroundAnchorStrategy`
- `overlayAnchorWindow`
- `overlayAnchorStrategy`

## 新边界

窗口解析仍然重要，但它不再用于“靠外部窗口实现真实背景”。

新的用途是：

- 找到 `SysListView32`，用于图标枚举和移动。
- 找到 Explorer PID，用于 Bridge 注入。
- 找到 Overlay 的安全锚点或诊断信息。
- 识别 Explorer 重启和句柄失效。

## 背景宿主规则

外部背景窗口只允许作为诊断/止血对象。

禁止：

- 强行显示 WorkerW。
- 强行拉伸 WorkerW。
- 把 Progman 当作真实背景插入宿主。
- 把 SHELLDLL_DefView 当作真实背景可见宿主。

没有天然安全宿主时必须返回明确策略，例如：

`NoSafeWorkerWAfterDefView`

## 执行步骤

1. 查找 `Progman`。
2. 枚举顶层窗口，找到 `SHELLDLL_DefView` 的父窗口。
3. 查找桌面 `SysListView32`。
4. 获取 Explorer PID。
5. 记录窗口类名、父子关系、可见性和窗口尺寸。
6. 在 Explorer 重启后重新解析。

## 验收标准

- 能稳定找到桌面 `SysListView32`。
- 能获得 Explorer PID。
- Explorer 重启后旧句柄失效能被识别。
- 日志能解释解析路径和失败原因。
- 不通过解析结果去破坏 WorkerW/Progman 的窗口状态。
