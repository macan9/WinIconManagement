# 01 架构原则和边界

## 核心原则

本项目不替代 Windows 桌面，也不自绘桌面图标。

正确方向是：

`Explorer 继续拥有桌面图标；应用拥有 Fence 数据、布局控制、背景绘制控制和恢复策略。`

## 关键架构分层

### Explorer 桌面控制层

负责：

- 解析 `Progman / WorkerW / SHELLDLL_DefView / SysListView32`。
- 枚举桌面图标。
- 读取图标身份、名称和坐标。
- 批量移动桌面图标。
- Explorer 重启后重新解析。

边界：

- 不接管 Explorer 的图标绘制。
- 不替换桌面右键、双击、拖拽等原生行为。

### Explorer Bridge 进程内背景层

负责：

- 将受控 DLL 加载到 Explorer 进程。
- 在 Explorer 进程内定位桌面 `SysListView32`。
- 接收主程序发送的 Fence 几何和样式数据。
- 优先尝试 Explorer 进程内 `LVM_SETBKIMAGEW` 背景图路径。
- 必要时再进入 Explorer 内 subclass 绘制路径。

边界：

- Bridge 只处理 Fence 背景绘制，不处理图标业务数据。
- Bridge 必须可恢复、可重入、可随 Explorer 重启清理。
- Bridge 不能阻塞 Explorer UI 线程。
- Bridge 不能在 Explorer 内执行复杂业务逻辑。

### Overlay 前景交互层

负责：

- 框选过程中的临时矩形。
- 确认/取消小面板。
- 活动 Fence 的边框、标题、删除按钮、缩放手柄等前景提示。

边界：

- Overlay 不再绘制真实 Fence 背景填充。
- Overlay 不能作为桌面背景层。
- Overlay 不能依赖全屏透明窗口承担复杂输入。
- Overlay 必须默认 click-through，只在明确热区接管输入。

### 运行时与数据层

负责：

- Fence 集合。
- Fence 与图标归属关系。
- 图标原始坐标和当前目标坐标。
- 启动、退出、Explorer 重启和异常退出恢复策略。

## 已证伪路线

以下路线不再继续推进：

- 用全屏 Overlay 假装 Fence 背景。
- 将 `BackgroundWindow` 挂到 `SHELLDLL_DefView` 并期望它显示在 `SysListView32` 下。
- 将 `BackgroundWindow` 挂到 `WorkerW` 后强行 resize/show。
- 将 `Progman` 当作普通可插入背景宿主。
- 通过外部窗口 Z 序试错实现真实图标底层背景。

这些路线已经导致过背景不可见、图标遮挡、全屏白幕和任务栏被遮挡等问题。

## 不做什么

- 不自绘桌面图标。
- 不把 Overlay 当成新的桌面。
- 不把 Overlay 或 BackgroundWindow 硬塞成桌面图标父窗口。
- 不强行显示、拉伸、重排 Explorer 的 WorkerW/Progman。
- 不让任何全屏窗口遮住任务栏、托盘、普通窗口或桌面右键。

## 最终验收标准

1. 图标仍由 Explorer 原生绘制。
2. Fence 背景由 Explorer 进程内路径绘制或应用到 Explorer 自有绘制入口。
3. 图标视觉上位于 Fence 背景之上。
4. Overlay 只承担前景提示和小范围交互。
5. 启动、退出、Explorer 重启、异常退出后可恢复。
