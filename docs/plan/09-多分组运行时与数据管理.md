# 10 多分组运行时与数据管理

## 目标

在 `08-09` 已完成单分组闭环的基础上，把运行时模型正式扩成多分组，并补上与多分组直接相关的数据管理能力。

本阶段的核心不是“做设置页”，而是先把多分组的底层运行逻辑和数据操作收稳。

## 前置条件

进入本阶段前，应先满足：

- `08`：单分组创建能力可用
- `09`：单分组退出恢复、再次启动恢复闭环可用

如果单分组闭环还不稳定，不应继续把复杂度推到多分组。

## 范围

本阶段统一承接三类工作：

1. 多分组运行时状态
2. 多分组恢复与重建
3. 多分组基础数据管理

## 需要在本阶段收掉的遗留项

- 左键框选与桌面空白区输入边界继续回归验证
- `WH_MOUSE_LL` 按需启用继续验证稳定性
- 图标命中规则从“点坐标”升级到“考虑图标尺寸和文本区域”
- 分组背景从持久化数据恢复并显示
- Explorer 原生交互边界继续收紧，避免影响托盘、任务栏、普通窗口和桌面图标原生行为
- 分组容量不足时的统一策略明确下来

## 开发内容

### 1. 多分组运行时模型

- 将当前“单个当前分组”状态改为“分组集合”
- 为每个分组分配稳定 `fence_id`
- 区分：
  - 持久化后的正式分组
  - 当前临时框选矩形
  - 当前确认中的待创建分组
  - 当前选中/当前编辑分组

### 2. 多分组创建与绘制

- 支持连续创建多个矩形分组
- 每次确认绘制后追加一个新分组，而不是覆盖当前矩形
- 浮层统一绘制多个正式矩形背景
- 当前活跃分组需要有明确选中态

### 3. 多分组恢复与重建

- 启动时加载全部分组并统一绘制
- 启动时按全部分组恢复图标布局
- 退出时按全部分组恢复原始图标
- 某个分组恢复失败时，不阻塞其他分组恢复

### 4. 多分组基础数据管理

- 创建分组时追加 `Fence` 记录，不覆盖旧记录
- 启动时读取全部 `Fence` 和对应 `FenceIcons`
- 定义分组显示顺序
- 补充分组删除、更新、重排所需的持久化接口
- 提供当前分组切换所需的数据读取能力

## 与 11 的边界

本阶段只做“多分组运行时 + 多分组数据管理”的底层闭环。

以下内容明确放到 `11`：

- 设置页中的分组列表 UI
- 重命名、删除、排序的可视化交互入口
- 分组拖动、缩放、锁定等编辑控件
- 全局设置和单分组设置的界面组织

## 产出物

- 多分组创建能力
- 多分组持久化加载与绘制能力
- 多分组退出恢复与再次启动恢复能力
- 多分组基础数据管理接口

## 验收标准

- 用户可以连续绘制多个矩形分组
- 每个分组都能独立保存位置、尺寸和图标关系
- 重新启动后，全部已保存分组都能重新显示
- 全部托管图标都能回到各自分组
- 多分组存在时，普通桌面交互不被明显破坏
- 删除、更新、重排所需的数据接口具备接入 `11` 的条件

## 风险点

- 现有单分组状态变量较多，直接扩成多分组容易遗漏
- 浮层输入和桌面原生输入的边界会比单分组更复杂
- 如果没有先定义“当前分组”和“显示顺序”，后续设置页会很难收敛

## 推荐拆分顺序

1. 先把运行时状态从“单分组”改成“分组集合 + 临时框选”
2. 再把浮层绘制改成“可绘制多个正式分组”
3. 接着补启动加载全部分组、退出恢复全部分组
4. 最后补齐删除、更新、重排等基础数据管理接口

## 非目标

当前阶段不要求一次性完成以下能力：

- 完整动画系统
- 分组吸附、自动避让等高级布局
- 跨虚拟桌面同步
- 重型可视化设置界面
