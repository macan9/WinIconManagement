# 09 Overlay 无侵入显示与输入边界

## 当前状态

本阶段已经有实现雏形，当前任务是收口验收，而不是从零开始。

已具备：

- `OverlayWindow` 基础分层窗口。
- 临时框选矩形和确认弹层。
- 基础 click-through 和桌面层级锚定。
- 编辑态小范围热区雏形。

本轮收口进展：

- 已去掉无真实 Fence 时的默认假 Fence 显示。
- 已保持 Overlay 默认 click-through。
- 已将编辑移动热区收窄到顶部标题栏范围。
- 已保留删除按钮和右下角缩放柄为小范围热区。

## 目标

实现一个**不扰动桌面原生交互**的 Overlay 基础层。

本阶段不要求已有真实 Fence，也不负责验证真实 Fence 的显示效果；它只负责证明：

`即使 Overlay 存在，Windows 桌面仍然像原来一样工作。`

## 开发内容

- 创建原生分层窗口 `OverlayWindow`
- 配置扩展样式：`WS_EX_LAYERED`、`WS_EX_TOOLWINDOW`、`WS_EX_NOACTIVATE`
- 默认保持 click-through，不承担大面积输入
- 支持临时框选矩形和确认弹层
- 提供小范围编辑热区基础能力
- 处理多显示器虚拟桌面区域
- 处理 DPI 坐标转换
- 控制 Overlay 的桌面层级位置

## 核心原则

这一层只负责“存在但不打扰”，不负责“展示真实 Fence 内容”。

必须避免两类错误：

1. 粗暴改 `SetParent` 或硬塞桌面宿主，导致可见性和输入失控。
2. 让全屏 Overlay 接管大量鼠标事件，导致任务栏、托盘、右键异常。

## 产出物

- `OverlayWindow`
- 安全的桌面层级控制
- 默认透明穿透能力
- 临时矩形和确认弹层能力
- 小范围热区基础能力

## 验收标准

- 无真实 Fence 时不显示默认假 Fence
- 桌面图标原生双击与右键不被破坏
- 桌面空白区右键不被破坏
- 任务栏、托盘、普通窗口交互不被影响
- 退出后 Overlay 窗口完整销毁

## 当前验收状态

- 已完成：无真实 Fence 时不显示默认假 Fence。
- 已完成：默认透明穿透，不让 Overlay 窗口直接接管桌面输入。
- 已完成：编辑态只保留标题栏、删除按钮、缩放柄三个小范围入口。
- 待验证：桌面图标双击和右键。
- 待验证：桌面空白区右键。
- 待验证：任务栏、托盘、普通窗口右键和点击。
- 待验证：多显示器和 Explorer 重连后的 Overlay 层级恢复。

## 边界

本阶段不验收：

- 真实 Fence 背景、边框、标题显示。
- 活动态高亮是否正确。
- 依赖真实 Fence 的编辑态显示与联调。

这些内容转入 `11-2`。

## 执行顺序

1. 验证无 Fence 空状态。
2. 验证桌面图标双击和右键。
3. 验证桌面空白区右键。
4. 验证任务栏、托盘、普通窗口点击和右键。
5. 验证显示器变化和 Explorer 重连后的层级恢复。

## 风险点

- 层级放错会导致 Overlay 看不见或压住桌面。
- 全屏窗口如果承担交互，极易破坏系统行为。
- 分层透明绘制需要控制重绘成本。

## 与主线关系

这是单 Fence 主链的前置收口阶段。

做完后，`10` 才能在不破坏桌面的前提下继续推进框选创建；而依赖真实 Fence 的 Overlay 显示验收，则在 `11-2` 做联合回归。
