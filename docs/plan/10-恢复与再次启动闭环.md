# 09 单分组退出恢复与再次启动闭环

## 目标

完成“08 创建的第一个分组”在退出和再次启动之间的单分组闭环。

本阶段明确先不扩展多分组产品承诺，只保证：

- 能创建一个分组
- 退出时恢复这一个分组托管的图标
- 再次启动时恢复这一个分组的背景和图标布局

数据模型可以继续保留多分组兼容性，但 `09` 的业务验收口径按单分组闭环执行。

## 开发内容

- 退出时读取当前单分组托管图标的原始坐标
- 将当前单分组托管图标恢复到原始位置
- 停止鼠标 Hook 和交互状态
- 销毁单分组原生浮层或单分组可视层
- 删除托盘图标
- 关闭 SQLite 数据库
- 释放 Win32 资源
- 启动时读取当前单分组配置
- 启动时重新枚举桌面图标
- 匹配当前单分组托管图标
- 重建单个矩形背景
- 将匹配图标重新移动到该分组内
- 处理缺失图标、重命名图标、数量变化
- 增加异常退出检测

## 单分组边界

- 本阶段只要求一个当前分组闭环，不要求顺序恢复多个分组
- 如果底层已经保留多条 `Fence` 记录，业务层需要明确只选择一个当前分组参与恢复
- 多分组恢复顺序、失败隔离、显示顺序，统一放到 `10`

## 产出物

- 退出恢复流程
- 再次启动恢复流程
- 异常退出后的恢复入口

## 验收标准

- 正常退出后，当前分组托管图标恢复到原始位置
- 正常退出后，当前分组背景消失
- 正常退出后，托盘图标消失
- 再次启动后，当前已保存分组背景重新出现
- 再次启动后，对应图标重新进入该分组
- 某个图标恢复失败时，不会拖垮整个应用启动

## 风险点

- 恢复失败可能导致用户桌面布局混乱
- 图标身份匹配不稳定会影响单分组恢复成功率
- 如果本阶段边界不收紧，代码会过早卷入多分组复杂度，导致闭环不稳
