# 11-1 真实 Fence 桌面背景层实现

## 文档定位

本文承接 `09` 和 `10`，但先于原先的“显示与编辑态联调”。

- `09` 只验证 Overlay 无侵入存在。
- `10` 负责真正创建出第一个 Fence。
- 本阶段负责解决一个更底层的问题：`真实 Fence 不能继续依赖 Overlay 直接填充显示`。

## 当前问题

当前实现里，Fence 的可视矩形仍然由 `OverlayWindow` 直接绘制。

这会带来一个结构性问题：

- Overlay 是顶层分层窗口。
- 它即使 click-through，也仍然是画在桌面图标视觉层之上。
- 因此只要在 Overlay 上直接填充 Fence 背景，图标就会看起来被罩住。

这不是“透明度再调一下”可以真正解决的问题，而是宿主层级选错了。

## 目标

把“Fence 背景层”和“Overlay 交互层”彻底分开：

- Fence 背景层负责出现在桌面图标之下。
- Overlay 只负责轻量边框、选中态、编辑热区、确认弹层等前景交互提示。

本阶段完成后，要建立新的结构前提：

`真实 Fence 背景不再通过 Overlay 直接填充实现。`

## 本阶段聚焦

- 明确真实 Fence 背景层的宿主策略
- 明确 Overlay 与背景层的职责边界
- 落地第一个可运行的桌面背景层方案
- 保证图标视觉上不再被 Fence 背景遮住
- 保证 Explorer 重连后背景层可以重新挂回正确位置

## 开发内容

- 分离“背景绘制”和“交互绘制”两套运行时职责
- 为真实 Fence 引入桌面背景层宿主
- 保留 `OverlayWindow` 作为前景交互层
- 让背景层只消费 Fence 几何和样式数据
- 让 Overlay 只消费活动态、热区、确认 UI 和辅助描边
- 处理背景层在多显示器与 DPI 下的坐标映射
- 处理 Explorer 重建后的背景层重新附着

## 关键原则

- 不能再把“真实 Fence 背景”继续画在 Overlay 上冒充桌面背景
- 不能为了下沉层级而破坏桌面原生输入链
- 背景层和 Overlay 层必须职责单一，避免继续缠绕
- 如果底层宿主策略不稳定，宁可先只显示边框，也不要继续做假背景

## 验收标准

- 创建真实 Fence 后，图标视觉上不再像被半透明层罩住
- Fence 背景与图标层级关系正确
- Overlay 前景提示仍然可用
- Explorer 重连后背景层能恢复
- 多显示器下背景位置不漂移

## 不在本阶段解决

- 完整编辑态联调
- 删除、重命名、移动、缩放的完整闭环
- 多 Fence 并存时的完整背景层管理

这些内容转入后续阶段。

## 执行顺序

1. 复盘当前 Overlay 直接填充方案的层级问题。
2. 设计真实 Fence 背景层与 Overlay 前景层的职责拆分。
3. 落地第一个桌面背景层宿主方案。
4. 验证单 Fence 创建后的视觉层级是否正确。
5. 验证 Explorer 重连和多显示器场景。

## 与主线关系

这是阶段十一真正的起点。

如果这一步不先做，后面的“显示联调”和“编辑闭环”都会建立在错误的层级方案上，越做越难收口。
