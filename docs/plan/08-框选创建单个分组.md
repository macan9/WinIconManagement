# 08 框选创建分组

## 目标

实现用户在桌面空白区长按左键拖动框选区域，并将区域内图标收纳到新分组中的第一版核心体验。

本阶段聚焦“创建第一个可工作的矩形分组”：

- 在桌面空白区发起框选
- 绘制临时框选矩形
- 识别命中的桌面图标
- 生成一个矩形分组背景
- 将命中图标移动到分组内并自动排列
- 保存分组与图标关系

多矩形/多分组能力，以及本阶段遗留项的系统性收尾，统一转入 `08-1`。

## 开发内容

- 实现 `MouseController`
- 优先使用桌面/浮层已有输入链路，必要时按需启用 `WH_MOUSE_LL`
- 判断桌面空白区左键拖动行为
- 绘制临时框选矩形
- 枚举当前桌面图标
- 根据图标坐标判断是否命中框选区域
- 创建第一条分组记录
- 记录命中图标原始位置
- 计算分组内网格位置
- 将图标移动到分组内
- 保存分组和图标关系
- 框选结束后释放临时交互状态

## 产出物

- 框选创建分组能力
- 第一条完整的图标收纳闭环
- 临时框选绘制能力

## 验收标准

- 用户能通过拖拽在桌面创建矩形区域
- 框选区域内图标能被识别
- 被选中图标能移动到矩形区域内并自动排列
- 分组背景能保存并显示
- 未选中的图标不受影响

## 当前阶段边界

- 当前阶段默认只要求创建第一个分组，不要求顺序创建多个分组
- 当前阶段不处理分组列表管理、分组删除、分组重排
- 当前阶段不要求完整覆盖重启恢复、设置编辑、Explorer 重启后的多分组重建

## 已知遗留项

以下内容不再继续塞进 `08`，统一在 `08-1` 中收口：

- 多矩形/多分组创建与显示
- 分组背景从持久化恢复并显示
- 图标命中规则考虑图标尺寸和文本区域
- 分组容量不足时的布局和提示策略
- 多分组下的退出恢复、再次启动恢复、设置编辑、稳定性增强

## 风险点

- 框选操作不能过度破坏 Explorer 原生桌面交互
- 低级鼠标 Hook 必须按需启用并及时释放
- 图标命中判断不能长期停留在简化版点坐标模型
- 如果 08 继续叠加多分组能力，会让阶段边界和验收口径变得混乱
