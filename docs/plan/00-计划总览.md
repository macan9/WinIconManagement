# 计划总览

## 文档分工

`docs/plan` 只保留三层职责，避免同一件事在多处重复维护：

- `00-计划总览.md`：导航、阶段分组、当前执行指针。
- `01-架构原则和边界.md`：架构原则和边界，只回答“为什么这样做、什么不能做”。
- `02-执行路线图.md`：唯一的执行顺序和细分步骤，只回答“先做什么、后做什么”。
- `03` 到 `15`：阶段卡片，只写该阶段的目标、范围、产出和验收标准。

## 总目标

本项目采用 **Explorer 控制主导** 方案实现桌面分组能力。

一句话定义：

`Windows 继续画桌面图标；应用负责 Fence 容器、图标归属、目标坐标、自动排布、编辑和恢复。`

这意味着：

- 桌面图标仍由 `Explorer / SysListView32` 原生绘制。
- 应用只绘制 Fence 背景、标题、活动态和小范围编辑控件。
- 应用通过 Explorer 桌面 ListView 控制图标位置。
- 输入处理必须小范围、可退出、可回归，不能让全屏 Overlay 接管桌面。

## 当前执行指针

当前不要从 `03` 重新开始，也不要直接跳到多 Fence。

下一步从：

`09-Fence背景层与桌面层级控制.md`

准确说，是先做 `09` 的收口验收：确认 Overlay 在**没有真实 Fence** 时也不会破坏桌面图标、任务栏、托盘、普通窗口的原生交互。

完成 `09` 后，执行顺序是：

1. `10` 收口单 Fence 框选创建闭环。
2. `11-0` 先解决桌面背景层宿主与层级锚定。
3. `11-1` 再收口真实 Fence 背景绘制最小闭环。
4. `11-2` 再收口前景 Overlay 显示联调。
5. `11-3` 再收口单 Fence 编辑热区与预览态。
6. `11-4` 最后收口单 Fence 编辑提交闭环。
7. `12` 扩展多 Fence 运行时。
8. `14` 做完整启停恢复与 Explorer 重启恢复。
9. `13` 做设置界面。
10. `15` 做稳定性增强。

`14` 的部分基础能力可以提前穿插，但完整验收放在多 Fence 运行时稳定之后。

## 主线验收口径

最终完成时，应满足：

1. 桌面图标仍由 Windows 原生绘制。
2. 图标视觉上稳定地落在 Fence 区域之上。
3. Fence 绘制不破坏桌面、任务栏、托盘、普通窗口的右键和点击。
4. 应用能稳定维护图标与 Fence 的归属和布局。
5. 启动、退出、Explorer 重启、异常退出后都能恢复到正确状态。
