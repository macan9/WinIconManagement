# 03 项目初始化

## 目标

建立可长期演进的 Win32/C++ 项目骨架，为 Explorer 控制主导、Bridge 进程内绘制、图标布局控制、持久化和恢复能力提供基础。

本阶段不实现业务闭环，只保证工程结构、构建链路、日志和基础生命周期可靠。

## 模块边界

推荐目录职责：

- `App`：主程序控制器、窗口消息、阶段调度。
- `Desktop`：Explorer 桌面窗口解析、图标枚举与坐标控制。
- `Background`：外部背景窗口的诊断/止血代码，不再作为最终背景主路径。
- `ExplorerBridge`：后续新增，负责 Explorer 进程内背景绘制。
- `Overlay`：前景提示、框选、编辑热区。
- `Interaction`：鼠标输入边界、小范围热区。
- `Persistence`：SQLite 数据库和恢复状态。
- `Tray`：托盘入口和应用生命周期。
- `Infrastructure`：日志、路径、DPI、通用工具。

## 构建要求

- 保留单一 `build` 链路，不新增重复 build 目录。
- 主程序 target 为 `WinIconManagement.exe`。
- 后续 `10` 阶段新增 `ExplorerBridge.dll` target。
- 所有构建变更必须能通过 `cmake --build build --config Debug`。

## 日志要求

从项目初始化开始就必须有日志：

- 应用启动和退出。
- 主窗口创建。
- 托盘创建。
- Explorer 解析结果。
- Bridge 注入结果。
- 背景绘制路径选择。
- 失败原因和回退路径。

日志是后续判断 Explorer 窗口层级、Bridge 生命周期和恢复流程的主要证据。

## 本阶段不做

- 不移动桌面图标。
- 不创建 Fence。
- 不绘制真实背景。
- 不注入 Explorer。
- 不做复杂设置界面。

## 验收标准

- 项目能稳定构建。
- 应用能启动、隐藏到托盘、退出。
- 日志目录和日志文件稳定生成。
- 工程结构支持后续新增 `ExplorerBridge.dll`。
- 退出后不残留可见窗口。
