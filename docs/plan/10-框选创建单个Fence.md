# 10 框选创建单个 Fence

## 当前状态

本阶段已有实现雏形，当前任务是稳定闭环。

已具备：

- `MouseController` 基础鼠标 Hook。
- 桌面空白区起手过滤。
- 临时框选矩形显示。
- 命中图标收集。
- 创建 Fence 记录。
- 批量移动命中图标到 Fence 内。
- 保存 Fence 与 FenceIcons。

下一步：

- 在 `09` 层级和输入边界收口后，再验证本阶段完整创建流程。
- 先保证单 Fence 创建稳定，再放开多 Fence 连续创建。

## 目标

实现用户在桌面空白区左键拖拽创建一个 Fence，并把命中的桌面图标纳入该 Fence 的第一版闭环。

本阶段聚焦：

- 发起框选
- 画出临时矩形
- 识别命中的桌面图标
- 创建一个 Fence
- 把命中图标移动到 Fence 区域并自动排布
- 保存 Fence 与图标关系

## 开发内容

- 实现 `MouseController`
- 优先只在桌面空白区允许起手
- 必要时启用 `WH_MOUSE_LL`
- 识别左键拖拽行为
- 绘制临时框选矩形
- 判断哪些桌面图标命中框选区域
- 创建第一条 Fence 记录
- 记录命中图标的原始坐标
- 计算 Fence 内目标坐标
- 批量移动桌面图标到 Fence 区域
- 保存 Fence 与 FenceIcons 关系
- 框选结束后释放临时交互状态

## 边界

本阶段只做“创建第一个 Fence”。

不在本阶段解决：

- 多 Fence 连续创建
- 完整设置界面
- 复杂恢复策略

## 产出物

- 框选创建单个 Fence 能力
- 第一条图标归组闭环
- 临时框选绘制能力

## 验收标准

- 用户可以在桌面空白区拖出 Fence
- 框选区域内图标能被识别
- 命中图标能移动到 Fence 区域并自动排布
- Fence 背景可保存并显示
- 未命中的图标不受影响

## 执行顺序

1. 验证桌面空白区起手过滤。
2. 验证临时框选矩形和确认流程。
3. 验证命中图标识别。
4. 验证 Fence 创建和持久化。
5. 验证图标进入 Fence 后的坐标布局。
6. 验证创建后刷新、重启加载和未命中图标不受影响。

## 风险点

- 框选起手不能破坏 Explorer 原生桌面交互
- 鼠标 Hook 必须按需启用并及时释放
- 图标命中规则不能长期停留在简化点坐标模型

## 与主线关系

这是 Explorer 控制主导方案中的第一个真实产品闭环：用户第一次看到“桌面图标进入 Fence 区域”。
