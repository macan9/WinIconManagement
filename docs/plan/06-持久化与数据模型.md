# 06 持久化与数据模型

## 目标

建立轻量 SQLite 持久化能力，保存应用设置、分组信息、图标位置和后续快照数据。

数据模型从一开始就要允许“一个应用实例管理多个矩形分组”，但业务接入顺序按阶段推进：

- `08-09` 先完成单分组闭环
- `10-11` 再接入多分组运行时、数据管理和设置界面

## 开发内容

- 集成 SQLite C API 或 `winsqlite3`
- 封装 `Database`
- 建立数据库版本管理机制
- 创建数据表：
  - `AppSettings`
  - `Fences`
  - `FenceIcons`
  - `Snapshots`
  - `SnapshotIcons`
- 实现基础 Repository：
  - `SettingsRepository`
  - `FenceRepository`
  - `SnapshotRepository`
- 实现事务封装
- 实现设置读写
- 实现分组读写
- 实现图标原始坐标和当前坐标保存
- 设计 `IconIdentity` 第一版生成规则

## 多矩形要求

- `Fences` 必须支持一条记录对应一个矩形分组
- `FenceIcons` 必须支持多个 `fence_id`
- 读取分组时要支持返回“全部分组”，而不是只取一条
- 后续应预留以下扩展字段：
  - `display_order`
  - `is_visible`
  - `is_locked`
  - `title`
  - `style_json`
- 后续设置页和恢复流程都应基于“分组集合”而不是“单个当前分组”

## 产出物

- SQLite 数据库文件
- C++ 数据访问层
- 设置、分组、图标关系的数据模型
- 数据库版本管理

## 验收标准

- 应用启动时能自动创建数据库
- 应用设置可以保存和读取
- 多个分组和图标位置可以保存和读取
- 数据库版本可识别
- 数据库连接和语句对象能正确释放

## 风险点

- 图标身份匹配第一版可能不够稳定
- 数据库损坏时需要降级处理
- 如果后续仍按单分组写业务逻辑，会浪费当前数据模型的一对多结构
