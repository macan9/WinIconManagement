本文是唯一执行路线图。

- 架构原则看 [01-架构原则和边界.md](./01-架构原则和边界.md)。

- 当前执行指针看 [00-计划总览.md](./00-计划总览.md)。

## 当前状态判断

当前代码已经不是从零开始的状态：

- `03-08` 的基础能力已经基本具备。
- `09` 的 Overlay 基础层已经有雏形，但仍需要收口层级、穿透和空状态。
- `10` 的框选创建单 Fence 已经有雏形，但需要稳定命中、创建、布局、持久化闭环。
- `11` 阶段原先把“真实 Fence 显示联调”和“底层背景层实现”混在了一起，需要先重排顺序。
- `11-0` 的单 Fence 编辑能力已经有部分实现，但需要在新的 11 阶段顺序下重新收口。
- `12` 以后不要提前扩张，避免单 Fence 状态和多 Fence 状态形成双真源。

因此当前不是回到第一步，而是从 `09` 开始做主链收口。

## 推荐执行顺序

### A. 基础底座确认

对应文档：

- `03-项目初始化.md`
- `04-托盘与应用生命周期.md`
- `05-桌面窗口解析.md`
- `06-桌面图标枚举与坐标读取.md`
- `07-桌面图标移动与还原验证.md`
- `08-持久化与数据模型.md`

当前处理方式：

- 不再重做。
- 只在后续阶段遇到缺口时回补。
- 每次改动后保留构建验证和关键日志。

完成条件：

- 能稳定连接 Explorer 桌面。
- 能枚举图标身份和坐标。
- 能批量移动和恢复图标。
- 能保存 Fence 和 FenceIcons。

### B. `09` Overlay 无侵入显示与输入边界

目标：

让 Overlay 成为可靠的无侵入基础层，而不是桌面替代层。

执行步骤：

1. 确认无真实 Fence 时不显示默认假 Fence。
2. 确认 Overlay 默认 click-through。
3. 确认选择确认弹层和编辑热区只在小范围接输入。
4. 确认任务栏、托盘、普通窗口、桌面右键不受影响。
5. 确认多显示器虚拟桌面坐标正确。
6. 确认 Explorer 重连后 Overlay 重新锚定和刷新。

完成条件：

- 桌面图标原生双击、右键正常。
- 任务栏、托盘、普通窗口点击和右键正常。
- 退出后 Overlay 窗口销毁完整。

### C. `10` 框选创建单个 Fence

目标：

完成第一个真实产品闭环：用户框选图标，创建 Fence，图标进入 Fence 区域，并保存关系。

执行步骤：

1. 空白区起手过滤。
2. 临时框选矩形绘制。
3. 命中图标识别。
4. Fence 矩形生成。
5. Fence 记录持久化。
6. FenceIcons 记录原始坐标和目标坐标。
7. 批量移动图标到 Fence 内。
8. 创建后刷新 Overlay 和诊断状态。

完成条件：

- 用户能创建一个 Fence。
- 命中图标能进入 Fence。
- 未命中图标不受影响。
- 重启应用后该 Fence 和图标关系仍可加载。

### D. `11-1` 真实 Fence 桌面背景层实现

目标：

先从底层解决“真实 Fence 背景继续画在 Overlay 上，会压在桌面图标之上”的结构性问题。

执行步骤：

1. 复盘当前 Overlay 直接填充的层级问题。
2. 拆分真实 Fence 背景层和 Overlay 交互层的职责。
3. 落地单 Fence 的桌面背景层宿主方案。
4. 验证图标视觉上不再像被 Fence 背景罩住。
5. 验证多显示器与 Explorer 重连后的背景层恢复。

完成条件：

- 真实 Fence 背景不再依赖 Overlay 直接填充。
- 图标视觉层级正确。
- 重连后背景层关系正确。

### E. `11-2` 真实 Fence 显示与编辑态联调

目标：

在 `11-1` 已经解决背景层问题的前提下，补完真实 Fence 的显示态、活动态和编辑热区联调。

执行步骤：

1. 验证标题、边框、活动态显示。
2. 验证当前活动 Fence 与前景提示一致。
3. 验证编辑热区位置和范围。
4. 验证预览态、提交态和取消态一致。
5. 验证创建后首帧显示和后续刷新稳定。

完成条件：

- 真实 Fence 可以稳定显示。
- 活动态和热区与当前活动 Fence 一致。
- 不再依赖下一次操作才补出显示状态。

### F. `11-0` 单 Fence 编辑闭环

目标：

让单个 Fence 可以安全编辑，并让图标布局与 Fence 几何一致。

执行步骤：

1. 统一当前活动 Fence。
2. 收紧编辑态视觉和热区。
3. 重命名当前 Fence。
4. 删除当前 Fence，并恢复其图标到原始坐标。
5. 移动 Fence，图标按偏移量跟随。
6. 缩放 Fence，图标按新几何重排。
7. 持久化 Fence 和 FenceIcons 更新。

完成条件：

- 重命名、删除、移动、缩放都可用。
- 删除后图标去向明确。
- 移动和缩放后图标位置与数据一致。
- 重新启动后编辑结果仍存在。

### G. `12` 多 Fence 运行时与数据管理

目标：

从单 Fence 扩展到可长期运行的多 Fence 模型。

执行顺序：

1. `12-1` Fence 集合运行时。
2. `12-2` 多 Fence 显示与活动态。
3. `12-3` 多 Fence 创建与加载。
4. `12-4` 多 Fence 数据管理。
5. `12-5` 多 Fence 交互边界。

完成条件：

- 可以连续创建多个 Fence。
- 每个 Fence 独立保存几何和图标关系。
- 启动后全部 Fence 能加载。
- 多 Fence 同时存在时输入边界仍清晰。

### H. `14` 启停恢复与 Explorer 重启闭环

目标：

把恢复能力从“局部可用”收成完整可靠闭环。

执行顺序：

1. `14-1` 正常退出恢复。
2. `14-2` 再次启动恢复。
3. `14-3` Explorer 重启恢复。
4. `14-4` 异常退出保护。
5. `14-5` 恢复回归测试。

完成条件：

- 正常退出后桌面状态符合恢复策略。
- 再次启动后 Fence 和图标布局可恢复。
- Explorer 重启后能自动重连和重建。
- 异常退出后下次启动能进入安全恢复路径。

### I. `13` 设置界面与分组编辑界面

目标：

在多 Fence 和恢复策略稳定后，再把底层能力暴露成用户可管理的界面。

执行内容：

- 全局设置。
- 恢复策略。
- Fence 列表。
- 当前 Fence 选择、重命名、删除。
- 基础诊断信息。

完成条件：

- 用户可以通过设置界面管理多个 Fence。
- 设置修改后可持久化。
- 设置界面和运行时状态一致。

### J. `15` 稳定性增强

目标：

补齐长期使用中的边界和回归质量。

执行内容：

- 输入边界。
- Z 序稳定性。
- 多显示器与 DPI。
- 性能与日志。
- 回归测试清单。

## 为什么从 `09` 开始

当前最容易拖慢后续工作的不是数据表，也不是 Explorer 枚举，而是 Overlay 的边界。

如果 `09` 不先收口，`10` 的框选确认、`11-1` 的背景层实现、`11-2` 的真实 Fence 联调、`11-0` 的编辑热区、`12` 的多 Fence 显示都会反复被层级和输入问题干扰。

因此当前从 `09` 开始，目标是：

`让 Overlay 只做可靠视觉层，让 Explorer 继续掌控真实桌面图标。`

## 每阶段执行格式

之后每次开工一个阶段，都按这个格式推进：

1. 读对应阶段卡片。
2. 对照当前代码列出已完成、待验证、待修复。
3. 先补验收缺口，再新增能力。
4. 构建验证。
5. 更新阶段文档状态或记录下一步。
