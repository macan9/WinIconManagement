# 08 持久化与数据模型

## 目标

建立 SQLite 持久化能力，保存 Fence、图标归属、布局、设置和恢复状态。

持久化层是单 Fence、多 Fence、Bridge 背景恢复、应用重启恢复和 Explorer 重启恢复的共同底座。

## 核心表

### fences

- `id`
- `name`
- `bounds`
- `display_order`
- `is_locked`
- `style_json`
- `created_at`
- `updated_at`

### fence_icons

- `fence_id`
- `icon_identity`
- `icon_name`
- `original_x`
- `original_y`
- `current_x`
- `current_y`
- `order_index`

### settings

- `key`
- `value`

### restore_sessions

- `exit_mode`
- `clean`
- `restore_needed`
- `managed_fence_count`
- `updated_at`

## 与 Bridge 的关系

Bridge 不直接访问数据库。

主程序负责：

- 从数据库加载 Fence。
- 生成运行时 Fence 状态。
- 把 Fence 几何和样式通过 IPC 发送给 Bridge。
- 在退出或恢复时决定是否清理 Bridge 背景。

## 执行步骤

1. 初始化数据库路径。
2. 建立 schema version。
3. 创建和迁移表结构。
4. 实现 Fence CRUD。
5. 实现 FenceIcon 保存和替换。
6. 实现 settings。
7. 实现 restore session。
8. 加入关键失败日志。

## 验收标准

- 首次启动能创建数据库。
- Fence 创建后能保存。
- 重启后能加载 Fence。
- 图标归属和坐标可恢复。
- schema 版本可检查。
- 数据库失败不会导致桌面状态被破坏。
