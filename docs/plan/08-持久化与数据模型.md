# 08 持久化与数据模型

## 目标

建立 SQLite 持久化能力，保存应用设置、Fence 信息、图标归属关系、原始坐标、目标坐标和恢复状态，为 Explorer 控制主导方案提供可靠数据底座。

## 开发内容

- 集成 `winsqlite3`
- 封装 `Database`
- 建立数据库版本管理机制
- 创建基础数据表：
  - `AppSettings`
  - `Fences`
  - `FenceIcons`
  - `RestoreSessions`
  - `Snapshots`
  - `SnapshotIcons`
- 实现基础 Repository：
  - `SettingsRepository`
  - `FenceRepository`
  - `SnapshotRepository`
- 实现事务封装
- 实现设置读写
- 实现 Fence 读写
- 实现图标原始坐标与当前目标坐标保存
- 设计 `IconIdentity` 的持久化字段

## 数据模型重点

本阶段必须把“图标属于哪个 Fence、原来在哪、现在应在哪、恢复时回到哪”表达清楚。

建议核心字段至少包括：

- `Fences`
  - `id`
  - `title`
  - `bounds`
  - `display_order`
  - `is_locked`
  - `is_visible`
  - `style_json`
- `FenceIcons`
  - `fence_id`
  - `icon_identity`
  - `original_x`
  - `original_y`
  - `current_x`
  - `current_y`
  - `slot_index`
- `RestoreSessions`
  - `last_exit_mode`
  - `last_shutdown_clean`
  - `last_restore_needed`

## 产出物

- SQLite 数据库文件
- C++ 数据访问层
- Fence 与图标归属关系模型
- 恢复状态模型

## 验收标准

- 应用启动时能自动创建数据库
- 应用设置可保存和读取
- Fence 和图标归属关系可保存和读取
- 原始坐标与当前目标坐标可正确持久化
- 数据库版本可识别

## 风险点

- 图标身份规则不稳会直接影响恢复成功率
- 如果一开始不把“原始坐标”和“目标坐标”区分开，后续恢复逻辑会混乱
- 数据库损坏时需要有降级处理

## 与主线关系

这是后续单 Fence、多 Fence、退出恢复、Explorer 重建恢复的共同数据底座。
