# 09 退出恢复与再次启动闭环

## 目标

完成应用退出后恢复原始桌面图标位置、再次启动后重建分组布局的闭环。

本阶段默认按“多矩形/多分组”设计，不再按单矩形假设实现恢复流程。

## 开发内容

- 退出时读取全部托管图标的原始坐标
- 将全部托管图标恢复到原始位置
- 停止鼠标 Hook 和交互状态
- 销毁全部原生浮层窗口或全部分组可视层
- 删除托盘图标
- 关闭 SQLite 数据库
- 释放 Win32 资源
- 启动时读取上次全部分组配置
- 启动时重新枚举桌面图标
- 匹配全部托管图标
- 重建全部矩形背景
- 将匹配图标重新移动到各自分组内
- 处理缺失图标、重命名图标、数量变化
- 增加异常退出检测

## 多矩形要求

- 退出恢复要覆盖全部分组，而不是最后一次创建的分组
- 再次启动时要按顺序恢复全部分组背景
- 某个分组恢复失败时，不能阻塞其他分组恢复
- 某个图标缺失时，要记录到对应分组的恢复结果，而不是中断整批流程

## 产出物

- 退出恢复流程
- 再次启动恢复流程
- 异常退出后的恢复入口

## 验收标准

- 正常退出后，全部托管图标恢复到原始位置
- 正常退出后，全部矩形背景消失
- 正常退出后，托盘图标消失
- 再次启动后，全部已保存矩形背景重新出现
- 再次启动后，对应图标重新进入各自分组
- 某个分组或图标恢复失败时，不会拖垮整个应用启动

## 风险点

- 恢复失败可能导致用户桌面布局混乱
- 图标身份匹配不稳定会影响多分组恢复
- 多分组下恢复顺序、冲突处理和部分失败日志都需要定义清楚
