# 14-1 矩形托举图标实施拆分
## 目标

基于 [14-矩形功能对接桌面图标实现.md](/d:/MyProjects/WinIconManagement/docs/plan/14-矩形功能对接桌面图标实现.md)，把“矩形真正托举图标”的大方案拆成可执行、可验收、可逐步回归的实施步骤。

这份文档不直接讨论最终愿景，而是回答两个更实际的问题：

1. 这件事应该分几步做。
2. 每一步做到什么程度，才可以进入下一步。

## 总原则

推进 `14` 主线时，必须遵守以下原则：

- 不在现有 `OverlayWindow` 上继续无限堆功能。
- 不一上来就隐藏 Windows 原生桌面图标。
- 不把“视觉像”误当成“真正接管”。
- 每一步都必须可启动、可调试、可回退。
- 每一步都要有清晰验收口，避免中途状态混乱。

## 推荐拆分总览

建议分 `6` 步推进：

1. 自绘图标原型
2. Shell 行为桥接
3. 托管运行时落地
4. 矩形驱动图标布局
5. 托管显示权切换
6. 启停与异常恢复闭环

这 `6` 步里，前 `3` 步是“跑通原型”，后 `3` 步是“收成稳定产品能力”。

---

## 第一步：自绘图标原型

### 目标

先让应用在矩形内部把图标画出来，并具备最基本的命中能力。

这一步的目标不是替代 Windows 桌面，而是验证：

- 我们能不能自己画图标
- 我们能不能自己识别图标点击
- 我们能不能建立“矩形内图标”的独立视图

### 范围

本步只做“显示和基础命中”，不做：

- 隐藏系统桌面图标
- 系统右键菜单
- 托管态恢复
- 完整拖拽排序

### 关键改动

建议新增模块：

- `src/DesktopHost/ManagedDesktopWindow.h/.cpp`
- `src/DesktopHost/ManagedIconRenderer.h/.cpp`
- `src/DesktopHost/IconHitTest.h/.cpp`

建议先接一条最短链路：

1. 从当前已存在的 `managedFences_` 中拿到某个矩形。
2. 从当前已存在的 `FenceIcons` 数据中拿到属于该矩形的图标。
3. 在一个独立承载窗口中把这些图标画到矩形内部。
4. 为每个图标生成本地绘制区域和命中区域。
5. 先支持单击选中高亮。

### 为什么要先做这一步

因为这是整个 `14` 主线的生死线。

如果这一步做不稳，后面的：

- 双击打开
- 右键菜单
- 拖拽排序
- 托管显示切换

都没有承载面。

### 验收标准

- 启动程序后，矩形内部可见应用自绘图标。
- 图标位置稳定，不依赖桌面重绘才显示。
- 鼠标点击图标时，应用能识别命中的是哪一个图标。
- 即使系统桌面图标仍然存在，矩形内自绘图标也能单独显示。

### 风险点

- 图标绘制窗口层级不对，导致看不见。
- 多屏坐标换算错误，导致图标画偏。
- 图标位图获取链路慢，导致首次渲染卡顿。

## 第二步：Shell 行为桥接

### 目标

让自绘图标具备“像桌面图标一样”的核心行为。

这一步重点不是布局，而是行为拟真：

- 双击打开
- 右键菜单
- 基础重命名入口

### 范围

本步仍然不做：

- 隐藏系统桌面图标
- 全量拖拽换位
- 启停恢复闭环

### 关键改动

建议新增模块：

- `src/Shell/ShellActionBridge.h/.cpp`
- `src/Shell/ShellContextMenuBridge.h/.cpp`
- `src/Shell/ShellIconProvider.h/.cpp`

需要打通：

1. 图标 identity 到系统对象的映射。
2. 双击时通过 Shell 能力打开对象。
3. 右键时通过 `IContextMenu` 拉起系统菜单。
4. 菜单执行后能刷新自绘层状态。

### 推荐顺序

1. 先支持普通文件和文件夹。
2. 再支持快捷方式。
3. 最后再补特殊对象兼容。

### 验收标准

- 常见文件可双击打开。
- 文件夹可双击打开。
- 快捷方式可正常触发目标。
- 右键能弹出系统上下文菜单。

### 风险点

- Shell 特殊对象不一定有稳定文件路径。
- 右键菜单可能依赖 PIDL 而不只是路径。
- 菜单回调完成后要刷新显示状态，否则界面会“假成功”。

## 第三步：托管运行时落地

### 目标

把当前“桌面快照 + 矩形背景”的逻辑升级为真正的托管运行时。

这一步的本质是：

把运行中的真源，从“每次看桌面现在是什么样”切成“应用自己知道图标现在是什么样”。

### 范围

本步重点是状态模型，不急着做最终显示切换。

### 关键改动

建议新增模块：

- `src/Runtime/ManagedDesktopRuntime.h/.cpp`
- `src/Runtime/ManagedFenceRuntime.h/.cpp`

建议新增数据对象：

- `ManagedIconInstance`
- `ManagedFenceRuntimeState`
- `ManagedDesktopSessionState`

需要完成：

1. 托管图标运行时对象化。
2. 矩形与图标关系运行时对象化。
3. 当前选中图标、当前活动矩形、拖拽中状态统一收口。
4. 绘制层不再直接拼接桌面原始数据，而是读取运行时对象。

### 为什么这一步很关键

如果没有这一层，系统还是会处在：

- 一边读 Windows 桌面
- 一边改 Windows 桌面
- 一边再把结果反推回矩形

这种状态会导致拖拽、缩放、恢复越来越乱。

### 验收标准

- 自绘图标能完全从运行时对象读取。
- 不刷新桌面快照时，矩形内图标仍能稳定显示。
- 运行时能明确知道每个矩形里有哪些图标、每个图标当前位置是什么。

### 风险点

- 现有 `AppController` 状态较多，收口时容易出现双真源。
- 持久化模型和运行时模型可能一开始不一致。

---

## 第四步：矩形驱动图标布局

### 目标

把“图标跟着桌面坐标走”改成“图标跟着矩形运行时布局走”。

也就是说：

- 移动矩形时，更新的是托管图标的相对布局
- 缩放矩形时，触发的是托管图标重排
- 图标拖拽时，改的是应用内的布局状态

### 范围

本步优先做规则网格，不急着做自由布局。

### 关键改动

建议新增模块：

- `src/Layout/IconLayoutEngine.h/.cpp`

并完成：

1. 图标在矩形内的格位计算。
2. 矩形缩放后的自动重排。
3. 图标拖拽后的换位或插入逻辑。
4. 矩形间拖拽转移。

### 建议策略

先统一用规则网格：

- 稳定
- 容易验收
- 容易与多分组联动

自由布局可以等后面再加。

### 验收标准

- 移动矩形时，图标整体跟随。
- 缩放矩形时，图标自动重排。
- 图标能在矩形内部拖拽换位。
- 图标能从一个矩形拖到另一个矩形。

### 风险点

- 拖拽状态和矩形编辑状态可能互相冲突。
- 多屏 DPI 下，相对坐标和实际像素坐标要统一。

---

## 第五步：托管显示权切换

### 目标

让被托管图标从“系统桌面显示为主”切换到“应用显示为主”。

这是第一次真正触碰“只显示一份图标”。

### 范围

这一步建议先做保守版，不要一步到位整体隐藏全部桌面图标。

### 推荐实现策略

#### 第一阶段：单图标隐藏迁移

对被托管图标做：

- 隐藏区迁移
- 不再在用户主视区保留原始显示

#### 第二阶段：整体验证后再考虑更彻底策略

如果单图标隐藏迁移稳定，再评估是否引入更彻底的“系统桌面整体隐藏 + 应用完全承载”。

### 关键改动

需要补：

- 托管图标隐藏状态字段
- 托管图标恢复字段
- 启动时重新应用隐藏策略

### 验收标准

- 被托管图标在用户主视区只显示一份。
- 用户操作的是应用里的那份图标。
- 重启应用后，隐藏/显示关系可恢复。

### 风险点

- 隐藏区策略在多显示器环境下可能不稳。
- Explorer 刷新后，图标可能重新回到系统桌面主视区。

---

## 第六步：启停与异常恢复闭环

### 目标

把这个能力真正收成一个可靠功能，而不是只在理想调试路径下可用。

### 范围

这一阶段要补齐：

- 启动恢复
- 退出恢复
- Explorer 重启恢复
- 异常退出保护

### 关键改动

建议补充：

- `SessionState`
- 恢复策略配置
- 启动自检逻辑
- 异常退出标记与兜底恢复

需要明确三种策略：

1. 退出恢复系统桌面
2. 退出保留托管态
3. 异常退出优先恢复安全态

### 验收标准

- 正常退出后，图标状态符合策略预期。
- 再次启动后，矩形和图标托管关系能恢复。
- Explorer 重启后，应用能重建托管状态。
- 异常退出后，用户不会误以为图标丢失。

### 风险点

- 启动恢复和退出恢复顺序错误，可能导致状态相互覆盖。
- 异常恢复如果没有单独标记，容易和正常恢复逻辑混淆。

---

## 阶段边界建议

为避免范围失控，建议明确边界：

### 前三步完成后

可以认为“矩形托举图标原型”成立。

这时应具备：

- 矩形内自绘图标
- 双击打开
- 右键菜单
- 基于应用运行时的数据驱动

但此时还不能认为已经完成了完整托管。

### 前四步完成后

可以认为“核心运行时已切换”。

这时矩形与图标关系已经从：

- 桌面图标坐标驱动

切成：

- 应用托管布局驱动

### 六步完成后

才算真正完成 `14` 主线闭环。

---

## 推荐实际开工顺序

建议按以下顺序推进，不要跳步：

1. 第一步：自绘图标原型
2. 第二步：Shell 行为桥接
3. 第三步：托管运行时落地
4. 第四步：矩形驱动图标布局
5. 第五步：托管显示权切换
6. 第六步：启停与异常恢复闭环

原因很简单：

- 如果先做隐藏系统图标，风险太大
- 如果没有自绘图标和运行时，隐藏后就没有稳定承载面
- 如果没有恢复闭环，后期很容易把用户桌面搞乱

---

## 建议当前立即进入的步骤

当前最适合直接开做的是第一步：

`自绘图标原型`

先把“矩形内部由应用自己绘制图标”做出来，这是整个 `14` 路线最关键的落点。

只有这一步站稳，后面的托管、隐藏、恢复，才有意义。
