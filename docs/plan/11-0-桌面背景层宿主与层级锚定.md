# 11-0 桌面背景层宿主与层级锚定

## 目标

先只解决一个最底层的问题：

`真实 Fence 不能继续依赖 Overlay 充当背景层。`

本阶段只负责把真实 Fence 背景层挂到正确的桌面宿主链路上，并确认它和桌面图标的前后层级关系是正确的。

这里要特别收紧范围：

- `11-0` 不负责解决“背景填充已经能稳定看见”
- `11-0` 不负责解决“背景样式已经完整正确”
- `11-0` 只负责先证明“真实背景层已经脱离 Overlay，并挂在正确桌面宿主关系里”

## 本阶段只做什么

- 明确真实背景层的宿主窗口选择策略
- 明确背景层与 Overlay 的职责边界
- 落地第一版真实背景层窗口骨架
- 处理 Explorer 重连后的重新挂接
- 验证背景层已经不再走 Overlay 伪装路径
- 验证桌面输入链没有因为背景层挂接被破坏

## 本阶段不做什么

- 不追求背景层的完整视觉样式
- 不以“背景填充颜色已经稳定可见”作为本阶段完成标准
- 不收口标题、活动态、编辑态提示
- 不收口移动、缩放、删除、重命名
- 不扩展到多 Fence 完整管理

## 关键问题

- 真实背景层应该附着到哪个桌面宿主
- 它如何保持在桌面图标之下或与桌面层级关系正确
- Explorer 重启或桌面句柄失效后如何重新锚定
- 如何避免为了下沉层级而破坏桌面输入链
- 如何让背景层的宿主选择和回退策略稳定，而不是继续混用多个临时路径

## 当前阶段结论

对于当前主链，`11-0` 的主问题不是“背景为什么还没显示出来”，而是：

- 背景层到底挂到了谁身上
- 它是不是仍然在走 Overlay 假装背景
- 它在 Explorer 重连后是否还能回到同一套宿主关系

如果这三件事没有先收住，那么继续追背景颜色、填充、边框，都会把 `11-0` 和 `11-1` 混在一起。

## 验收标准

- 真实 Fence 背景不再由全屏 Overlay 直接填充
- 已经能够明确背景层当前宿主窗口与回退策略
- 背景层重连后仍能重新挂回桌面宿主
- 任务栏、托盘、普通窗口、桌面右键不被破坏
- 桌面图标点击、拖动、右键不因为背景层挂接而异常

以下现象仍允许在 `11-0` 结束时暂时存在：

- 背景填充还没有稳定可见
- 背景样式仍然很粗糙
- 需要进入 `11-1` 后再补齐首次显示和重绘闭环

## 执行顺序

1. 复盘当前 Overlay 直接充当背景层的层级问题。
2. 定义背景层宿主窗口选择与回退策略。
3. 明确 `BackgroundWindow` 和 `Overlay` 的职责边界。
4. 落地真实背景层窗口骨架与生命周期。
5. 接入 Explorer 重连后的重新锚定。
6. 做单 Fence 宿主关系和输入链正确性的人工验证。

## 与后续关系

这一段完成后，才适合继续做真实背景层绘制和前景联调。

换句话说：

- `11-0` 解决“挂在哪、怎么活着、怎么重连”
- `11-1` 解决“怎么画出来、什么时候画出来、为什么这次终于能看见”
