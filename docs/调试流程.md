# 调试流程

## 1. 目标

本文记录 C++ Win32 应用的基础调试流程，帮助后续遇到简单 bug 时快速定位问题。

前端开发里常见的定位方式是：

- 浏览器 DevTools 打断点
- 看 Console log
- 看 Network 请求
- 看 DOM 状态

C++ Win32 应用对应的方式是：

- VS Code / Visual Studio 打断点
- 看 Debug Output 和日志文件
- 看 Win32 API 返回值和 `GetLastError`
- 看窗口消息、句柄、资源生命周期
- 必要时用 Spy++ / Process Explorer / WinDbg 辅助观察

## 2. 推荐调试入口

日常推荐使用 VS Code：

```text
VS Code
+ CMake Tools
+ C++ extension
+ cppvsdbg
```

调试器类型使用：

```json
"type": "cppvsdbg"
```

`cppvsdbg` 是 Windows 上调试 MSVC 程序的推荐方式。

## 3. 基础调试步骤

### 3.1 Debug 构建

先生成 Debug 版本：

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build
```

Debug 构建应保留符号信息，方便断点和调用栈定位。

### 3.2 启动调试

VS Code 中按 `F5`，或者在 CMake Tools 中选择：

```text
CMake: Debug
```

调试时可以观察：

- Variables
- Watch
- Call Stack
- Breakpoints
- Debug Console

### 3.3 常见断点位置

Win32 应用优先在这些位置打断点：

- `WinMain`
- `AppController::Initialize`
- `WndProc`
- 托盘消息处理函数
- 菜单 command 分发函数
- `DesktopWindowResolver::Resolve`
- `DesktopIconService::Enumerate`
- `DesktopIconService::MoveIcon`
- `OverlayWindow::WndProc`
- `MouseController` 的鼠标按下、移动、释放逻辑
- SQLite Repository 的读写入口

## 4. launch.json 示例

如果使用 Ninja 单配置生成器，exe 可能在：

```text
build\WinIconManagement.exe
```

`.vscode/launch.json` 示例：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Debug WinIconManagement",
      "type": "cppvsdbg",
      "request": "launch",
      "program": "${workspaceFolder}/build/WinIconManagement.exe",
      "args": [],
      "stopAtEntry": false,
      "cwd": "${workspaceFolder}",
      "environment": [],
      "console": "internalConsole"
    }
  ]
}
```

如果使用 Visual Studio 多配置生成器，exe 可能在：

```text
build\Debug\WinIconManagement.exe
```

需要按实际输出路径调整 `program`。

## 5. 日志和 Debug Output

### 5.1 文件日志

项目应提供轻量滚动日志，用于记录：

- 应用启动和退出
- 托盘图标添加和删除
- 桌面窗口解析结果
- Explorer 进程 id
- `SysListView32` 句柄
- 图标枚举数量
- 图标移动和恢复结果
- SQLite 操作失败
- Win32 API 错误码

### 5.2 OutputDebugString

开发阶段可以使用 `OutputDebugStringW` 输出调试信息。

示例：

```cpp
OutputDebugStringW(L"[DesktopWindowResolver] Resolve started\n");
```

VS Code 调试窗口或 Visual Studio Output 面板可以看到这些信息。

也可以使用 Sysinternals DebugView 查看。

## 6. Win32 API 错误定位

很多 Win32 API 失败时不会抛异常，需要主动检查返回值。

示例：

```cpp
HWND hwnd = FindWindowW(L"Progman", nullptr);
if (!hwnd) {
    DWORD error = GetLastError();
    LogWin32Error(L"FindWindowW(Progman) failed", error);
}
```

常见模式：

```cpp
BOOL ok = SomeWin32Api();
if (!ok) {
    DWORD error = GetLastError();
}
```

注意：

- 不是所有 API 失败都会设置有意义的 `GetLastError`
- 调用其他 API 可能覆盖错误码
- 要在失败后立刻读取 `GetLastError`

## 7. 一个简单 bug 的调试例子

场景：点击托盘菜单“退出”，进程退出了，但托盘图标还残留一会儿。

### 7.1 先复现

步骤：

1. 启动应用
2. 确认托盘图标出现
3. 右键托盘图标
4. 点击退出
5. 观察托盘图标是否消失

### 7.2 打断点

优先断点：

- 托盘菜单 command 分发函数
- `AppController::Exit`
- `TrayIcon::Remove`
- 调用 `Shell_NotifyIcon(NIM_DELETE)` 的位置

### 7.3 看变量

重点检查：

- `NOTIFYICONDATA::cbSize`
- `NOTIFYICONDATA::hWnd`
- `NOTIFYICONDATA::uID`
- `Shell_NotifyIconW` 返回值
- 失败时的 `GetLastError`

### 7.4 判断原因

常见原因：

- 退出时没有调用 `NIM_DELETE`
- `hWnd` 和添加托盘图标时不是同一个窗口
- `uID` 和添加托盘图标时不一致
- 消息窗口已经先销毁，导致删除失败
- Explorer 正在重启，托盘状态短暂不同步

### 7.5 修复方向

修复时要保证：

- `TrayIcon::Remove` 在消息窗口销毁前调用
- 添加和删除使用同一组 `hWnd + uID`
- 删除失败时记录日志
- 应用退出流程只执行一次

## 8. 常见问题定位模板

### 8.1 窗口没有显示

检查：

- `CreateWindowExW` 返回值是否为 `nullptr`
- 是否调用 `ShowWindow`
- 是否调用 `UpdateWindow`
- 窗口样式是否包含不合适的隐藏或透明设置
- 父窗口句柄是否错误
- 是否被创建到屏幕外

### 8.2 菜单点击没有反应

检查：

- 是否收到 `WM_COMMAND`
- command id 是否正确
- 菜单创建和显示是否成功
- `TrackPopupMenu` 返回结果
- 消息窗口是否仍然有效

### 8.3 桌面图标枚举为空

检查：

- 是否找到 `SHELLDLL_DefView`
- 是否找到 `SysListView32`
- `LVM_GETITEMCOUNT` 返回值
- Explorer 是否刚重启
- 是否正在使用失效句柄
- 是否存在权限或跨进程访问问题

### 8.4 图标移动失败

检查：

- `SysListView32` 句柄是否有效
- 图标 index 是否仍然有效
- 目标坐标是否在桌面区域内
- Windows 是否开启自动排列图标
- `SendMessage` 是否返回预期结果
- 是否需要刷新 ListView

### 8.5 浮层挡住桌面图标

检查：

- 固定模式是否设置 `WS_EX_TRANSPARENT`
- 是否设置 `WS_EX_NOACTIVATE`
- hit test 是否错误返回可交互区域
- 浮层窗口层级是否过高
- 是否在图标区域错误拦截鼠标消息

### 8.6 内存持续上涨

检查：

- `HBITMAP`、`HBRUSH`、`HPEN`、`HFONT` 是否释放
- Direct2D / GDI+ 对象是否释放
- `HHOOK` 是否释放
- `sqlite3_stmt*` 是否 finalize
- `VirtualAllocEx` 是否对应 `VirtualFreeEx`
- 是否重复创建窗口或菜单但没有销毁

## 9. 推荐工具

VS Code：

- 打断点
- 看变量
- 看调用栈
- 单步调试

Visual Studio：

- 更强的原生 C++ 调试体验
- 资源文件和 Dialog 调试更方便

Spy++：

- 查看窗口句柄
- 查看窗口类名
- 查看窗口消息

Process Explorer：

- 查看进程
- 查看句柄
- 查看 DLL
- 查看 CPU 和内存

DebugView：

- 查看 `OutputDebugString`

WinDbg：

- 处理崩溃 dump
- 定位复杂 native 崩溃

## 10. 调试习惯

- 每个 Win32 API 失败路径都记录错误码
- 跨进程内存操作必须成对释放
- Hook、窗口、菜单、GDI 对象全部用 RAII 管理
- 桌面窗口句柄不要永久缓存
- 能复现再修，修完用同样步骤验证
- 对 Explorer 相关问题保留详细日志
- 对性能问题先测量，再优化
