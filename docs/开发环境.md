# 开发环境

## 1. 目标

本项目采用 **C++20 + Win32 + MSVC + Windows SDK + CMake + Ninja** 开发。

推荐日常开发方式：

```text
VS Code
+ CMake Tools
+ MSVC
+ Windows SDK
+ Ninja
+ cppvsdbg
```

## 3. 为什么普通 PowerShell 找不到 cl

MSVC 编译环境不只依赖 `PATH`，还依赖：

- `INCLUDE`
- `LIB`
- `LIBPATH`
- `WindowsSdkDir`
- `VCToolsInstallDir`
- 其他 Visual Studio 构建变量

这些变量通常由 `vcvars64.bat` 动态注入。

当前本机的初始化脚本位置：

```text
D:\Program Files\Microsoft Visual Studio\18\Community\VC\Auxiliary\Build\vcvars64.bat
```

如果普通 PowerShell 没有加载该脚本，直接执行下面命令可能找不到：

```powershell
cl
cmake --version
ninja --version
rc
```

## 4. 让普通 PowerShell 自动加载 C++ 环境

推荐将 Visual Studio C++ 环境自动注入 PowerShell profile。

执行一次：

```powershell
New-Item -ItemType File -Force $PROFILE | Out-Null; Add-Content $PROFILE 'cmd /s /c """D:\Program Files\Microsoft Visual Studio\18\Community\VC\Auxiliary\Build\vcvars64.bat"" >nul && set" | ForEach-Object { if ($_ -match "^(.*?)=(.*)$") { [Environment]::SetEnvironmentVariable($matches[1], $matches[2], "Process") } }'
```

然后重新打开 PowerShell，验证：

```powershell
cl
cmake --version
ninja --version
rc
```

预期结果：

- `cl` 输出 Microsoft C/C++ 编译器版本
- `cmake` 输出版本号
- `ninja` 输出版本号
- `rc` 输出 Windows Resource Compiler 信息

## 5. 临时加载 C++ 环境

如果不想修改 PowerShell profile，可以在当前终端临时加载：

```powershell
cmd /s /c """D:\Program Files\Microsoft Visual Studio\18\Community\VC\Auxiliary\Build\vcvars64.bat"" >nul && powershell"
```

或者直接使用 Visual Studio 自带的：

```text
x64 Native Tools Command Prompt for VS
```

## 6. VS Code 必装扩展

需要安装：

```powershell
& "D:\Microsoft VS Code\bin\code.cmd" --install-extension ms-vscode.cpptools
& "D:\Microsoft VS Code\bin\code.cmd" --install-extension ms-vscode.cmake-tools
```

推荐扩展：

```powershell
& "D:\Microsoft VS Code\bin\code.cmd" --install-extension twxs.cmake
```

说明：

- `ms-vscode.cpptools` 提供 C++ IntelliSense 和 `cppvsdbg` 调试器
- `ms-vscode.cmake-tools` 提供 CMake 配置、构建、调试入口
- `twxs.cmake` 提供 CMake 语法高亮

## 7. 推荐 CMake 生成方式

推荐使用 Ninja：

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build
```

如果使用 Visual Studio 多配置生成器：

```powershell
cmake -S . -B build -G "Visual Studio 18 2026" -A x64
cmake --build build --config Debug
```

项目初期建议优先使用 Ninja，目录更简单，VS Code 集成更轻。

## 10. 注意事项

- 不建议只把 `cl.exe` 所在目录手动加入 `PATH`。
- MSVC 需要完整构建环境变量，推荐始终通过 `vcvars64.bat` 初始化。
- VS Code 里如果 CMake 找不到编译器，先确认当前终端能执行 `cl`。
- 如果 VS Code 从桌面图标启动后找不到 `cl`，可以从已加载 C++ 环境的 PowerShell 中执行 `code .` 打开项目。
- 当前项目走原生 Win32 轻量路线，不需要安装托管桌面 UI 框架。
